# 聊天文件产物与 Git 管理

聊天中的文件结果卡片显示本轮发现的产物，默认展示三个文件，其余可以展开。文件按相对路径合并，保留预览当前文件、下载当前文件和在对话中引用的操作；旧聊天中的文件产物也保持可用。内部 `.pilotdeck` 文件不展示，其他点号文件（如 `.env`、`.gitignore`、`.github`）照常展示。

## 自动检查点与恢复已撤销

PilotDeck 不再在 Agent 回合、文件写入、Shell／Python 命令和后台任务前后创建检查点或文件备份，也不再持有覆盖整个 Agent Loop 的工作区锁。普通会话、Leader 和 Teammate 可以在同一目录进入模型执行阶段。

按轮或按会话的检查点变更、检查点历史、恢复预览、文件与对话回退、撤销恢复入口均已移除。停止执行不会自动撤销已经发生的文件修改。文件产物发现仍可能扫描目录，不承担备份或回滚职责。文件工具现有的读取新鲜度检查继续保留，避免覆盖读取后已经发生变化的内容。

已有聊天、检查点备份和工作区文件不会被删除。旧 transcript 中的恢复边界继续用于只读重放：聊天分页、模型上下文、Fork 和编辑最后一条可见消息仍遵守原来保留的分支，不重新显示隐藏历史。不再读取旧检查点备份来恢复文件。

旧 Gateway `manage_checkpoints` 始终返回 `CHECKPOINTS_REMOVED`；旧 HTTP `/api/checkpoints` 返回 HTTP 410 及同一错误码。新客户端不调用这些接口。

## Git

“探索”菜单中的 Git 入口打开独立侧栏；收起侧栏保留聊天草稿。Git 状态显示真实仓库的全部修改，包括手动编辑和其他会话产生的修改；不按已撤销的检查点自动选择文件。

支持初始化普通文件夹、查看和切换已有本地分支、查看暂存与未暂存差异、暂存／取消暂存、首次提交、提交、配置 origin、Fetch 和 Push。文件名通过 NUL 分隔状态解析和 literal pathspec 传递，保留空格、换行和重命名信息。

文件分组支持全选、取消选择、批量及单文件操作。已暂存和未暂存的选择相互独立，刷新保留仍然存在的选择。Commit 提交整个暂存区，并核对用户审阅时的 index tree；未暂存内容保留。Push 按已有跟踪关系推送当前分支；首次推送优先使用 origin，并设置跟踪分支。身份与凭据沿用系统 Git 配置。

Web `/api/git/operation` 使用独立 Gateway `repository_operation`，贯通 InProcess 和 Remote。操作包含项目及 Git 参数，由服务端解析项目路径、校验文件路径和提交状态。Git 修改之间使用短期仓库级互斥；Agent 回合不获取该锁，Git 不承诺隔离 Agent 或外部编辑器的写入。

项目内 `.pilotdeck` 目录保留自身的 `.gitignore`，不会修改根目录 `.gitignore` 或全局 Git 配置；已经被追踪的文件仍遵循 Git 的原有行为。

## 验证边界

自动化回归覆盖同目录会话在首个模型请求处并行、无新检查点、旧接口拒绝、用户备份保留、旧恢复边界分页与模型上下文、编辑最后消息和 Fork，以及 Git 暂存、提交、异常文件名与首次推送。

前端测试覆盖 Git 入口、侧栏关闭与草稿保留、文件产物预览／下载／引用、内部文件过滤和 Git 选择。该轮验证使用受控模型和工具，不包含真实模型端到端验收。
