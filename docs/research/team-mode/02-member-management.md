# Team 模式功能详解 · 模块 2：团队成员管理

> 本文保留 2026-10-14 的 **DSH 参考产品调研**，不是 PilotDeck 的已实现功能清单。除明确标注“PilotDeck”的段落外，文中的“当前版本”、工具、按钮和限制均指调研时的 DSH。PilotDeck 使用说明见 [docs/team-mode.md](../../team-mode.md)。
> 上级文档：[Team 模式用户功能清单](../team-mode-user-features.md)

> **PilotDeck 当前实现边界**：Teammate 的执行上下文属于 Team 运行段，用户通过团队交互面板处理权限询问、`ask_user_question` 和 `exit_plan_mode`。Teammate 的聊天只提供只读流式查看，不再提供可直接发送消息的独立会话输入框。成员模型、工作区和能力仍在团队详情中查看，交互面板不重复展示。

---

## 1. 这个模块解决什么问题

团队创建后只有一个 Leader。真正干活的成员要在团队运行中逐个创建。本模块说明：成员是什么、怎么创建、有哪些状态、每个状态下能做什么操作、各操作的确认提示和后果。

---

## 2. Leader 与成员

### 2.1 Leader

- 每个团队**恰好一个** Leader。它就是创建团队时打开的那个会话。
- Leader 的身份、人设、工具来自蓝图的 `leader` 字段。
- Leader 不能被归档、恢复或处置。关闭团队就是停止使用这个会话。
- 用户直接和 Leader 对话，就像普通会话一样。区别是 Leader 多了一套团队协作工具，见模块 3。

### 2.2 成员

- 成员由 Leader 用工具创建，或由人类在团队视图里点"+"创建。
- 每个成员基于蓝图里的一个**角色模板**创建。同一个模板可以创建多个成员。
- 每个成员拥有 Team 内部的独立执行上下文和对话历史，默认**不**知道 Leader 和其他成员聊了什么。
- 成员的身份是系统分配的实例编号（形如 `inst-xxxx`），不是名字。两个成员可以同名，系统不会混淆。
- 成员的人设、工具、权限来自它所属的角色模板，创建时冻结。

### 2.3 创建成员时可以指定什么

| 字段 | 必填 | 规则 | 说明 |
| --- | --- | --- | --- |
| 角色模板 | 必填 | 蓝图里定义的模板之一 | 决定成员的人设、工具、权限、工作模式 |
| 标签 | 必填 | 1 到 128 字符 | 显示名，例如"研究员-1"。可以重复 |
| 分组 | 可选 | 1 到 128 字符 | 自由填写的分组标签，仅用于展示归类，没有任何权限或流程含义 |
| 工作区 | 可选 | 系统已登记的工作区之一 | 不填则继承团队默认工作区。**成员一旦开始运行，工作区不能再改**；要换目录就新建一个成员 |

人类在界面创建时填这些字段；Leader 用工具创建时传同名参数。

### 2.4 数量上限

受蓝图 `quotas` 约束：

- 整个团队累计创建总数、同时活跃数各有上限。
- **每个角色模板**各自还有累计数和同时活跃数上限。
- 超限时创建失败，并给出明确原因（团队总数超限 / 团队并发超限 / 该模板总数超限 / 该模板并发超限）。
- 已归档和已处置的成员仍计入"累计创建总数"，但不计入"同时活跃数"。

## 3. 成员状态

每个成员始终处于以下五个状态之一。界面用颜色点加文字显示。

| 状态 | 显示 | 含义 | 占用并发配额 |
| --- | --- | --- | --- |
| 已创建 | 🟡 琥珀色 | 刚创建，还没收到过任务 | 是 |
| 运行中 | 🔵 蓝色 | 正在执行任务 | 是 |
| 已结算 | 🟢 绿色 | 当前任务完成，等待新任务。对话历史保留 | 否 |
| 已归档 | 🟢 绿色 | 暂时停用，不接新任务。可恢复 | 否 |
| 已处置 | 🟢 绿色 | 永久停用。不能恢复，不接新任务。历史保留 | 否 |

状态转换：

```
已创建 ──收到任务──▶ 运行中 ──任务完成──▶ 已结算 ──收到新任务──▶ 运行中
                                            │
                                         归档 ▼
                                          已归档 ──恢复──▶ 已结算
任何非"已处置"状态 ──处置──▶ 已处置（终态）
```

几点说明：

- "已结算"的成员再收到任务会回到"运行中"，不需要先"恢复"。
- "已归档"的成员必须先"恢复"回到"已结算"，才能再收任务。
- "恢复"只是让成员重新可用，**不会**让它开始工作、不会调用模型、不会发任何消息。
- "处置"是单向的。处置后成员从活跃列表消失，但它的会话历史、对话记录、团队事件记录都保留，可以在团队事件和时间线里追溯。

成员的 AI 进程是否驻留在内存里，和上面的状态是两回事。一个"已结算"的成员可能已经被系统释放了进程，再收到任务时会自动唤醒，用户不需要手动"启动"它。

## 4. 在团队视图里管理成员

打开团队会话，点"团队"标签页，"成员组"区域显示全部成员。

### 4.1 成员组的布局

**Leader 组**（固定在最上面）

- 显示 Leader 名字和 `N 活跃`（当前活跃成员数）。
- 点击整行可以跳回 Leader 会话。
- 下方一行两个按钮和一个徽章：
  - **以 Team 模式打开 / 回到 Leader**：以完整团队功能打开 Leader 会话
  - **以普通模式打开**：把 Leader 会话当成普通会话打开，不加载团队功能（悬停提示"不执行 Team ensure；以普通 Session Agent 激活"）
  - 徽章显示当前是"Team 模式"还是"普通模式"
  - 失败时显示"以 Team 模式打开失败：原因"或"以普通模式打开失败：原因"

**角色模板组**（每个模板一组）

- 组标题：模板名 · `N 活跃`。
- 右侧"+"按钮：创建该模板的新成员。
- 模板下还没有成员时显示"尚无实例"。
- 展开后每个成员一行。

### 4.2 成员行显示什么

从左到右：

| 元素 | 内容 |
| --- | --- |
| 成员窗口 | DSH 可打开成员会话；PilotDeck 改为第 7 节的只读“查看聊天”，没有独立输入框 |
| 状态点 + 状态词 | 已创建 / 运行中 / 已结算 / 已归档 / 已处置 |
| 当前动作 | 成员正在做的事的一句话描述，没有时显示"暂无动作" |
| 待处理徽章 | DSH 展示成员待处理控制事项；PilotDeck 的权限、问题和 Plan 在独立团队交互面板处理 |
| 操作按钮 | 按状态显示可用操作，见 4.3 |
| 错误提示 | 上一次操作失败时显示"命令失败：错误码: 原因" |

### 4.3 每个状态下可用的操作

| 状态 | 可用按钮 | 说明 |
| --- | --- | --- |
| 已创建 | 发送任务… / 发送跟进 / 归档 / 处置 | "发送任务…"给它第一个任务 |
| 运行中 | 发送消息… / 发送跟进 / 归档 / 处置 | "发送跟进"追加指令 |
| 已结算 | 发送消息… / 恢复… / 归档 / 处置 | "恢复…"等于发新任务 |
| 已归档 | 恢复 / 处置 | "恢复"只是解除归档，不发任务 |
| 已处置 | 无 | 终态 |

同一个成员有操作正在进行时，这一行的所有按钮暂时禁用，显示"处理中…"。

注意两个"恢复"按钮的区别：

- **恢复…**（带省略号，已结算状态下）：打开输入框，让你写一段新任务发给成员。成员收到后进入运行中。
- **恢复**（不带省略号，已归档状态下）：直接把成员从"已归档"改回"已结算"，不弹窗、不发消息。

### 4.4 各操作的对话框

**创建成员实例**（点"+"）

| 字段 | 说明 |
| --- | --- |
| 模板 | 只读，显示所选模板名 |
| 标签 | 必填，占位提示"例如：研究员-1" |
| 分组（可选） | 自由填写 |
| 工作区（可选） | 下拉选已登记工作区；系统没有登记工作区时不显示 |

如果该模板是"一次性成员"模式，对话框顶部提示"新的委派会创建新实例。"

标签为空时"创建"按钮禁用。按钮：取消 / 创建。

**向 xxx 发送任务**（"发送任务…"或"恢复…"或"发送跟进"）

| 字段 | 说明 |
| --- | --- |
| 任务内容 | 必填，占位提示"描述要交给该成员的工作…" |

为空时"发送"禁用。按钮：取消 / 发送。

**给 xxx 发消息**（"发送消息…"）

| 字段 | 说明 |
| --- | --- |
| 主题（可选） | 一行 |
| 消息内容 | 必填，多行，占位提示"消息正文…" |

正文为空时禁用。按钮：取消 / 发送消息。

"发送任务"和"发送消息"的区别：任务会让成员开始一轮工作并有结果；消息只是告诉它一件事。见模块 3。

**归档该成员？**

- 成员运行中时正文："该成员正在运行。归档将停止当前工作，并在归档前排空其驻留子成员。"
- 其他状态正文："归档后，该成员将不再接收新的团队任务，直到恢复。"
- 按钮：取消 / 归档。

**处置该成员？**

- 正文："该成员无法再恢复或接收新的团队任务。其会话历史、Chat、Trajectory 与团队审计历史将保留。"
- 按钮：取消 / 处置。
- 界面上不会出现"删除"字样，因为什么都不会被删。

### 4.5 操作完成后

所有操作都是先提交到服务端，成功后刷新团队视图再显示新状态。界面不会"先乐观地改了再说"。如果操作成功但视图刷新失败，会显示"命令已完成，但团队视图更新失败：原因"，此时手动点"刷新团队视图"即可。

## 5. 归档和处置时发生了什么

用户点"归档"或"处置"一个**运行中**的成员时，系统按顺序做：

1. 停止接收给它的新任务。
2. 中断它当前正在做的事。
3. 等待它派出的子代理全部结束。
4. 释放它的 AI 进程。
5. 记录状态变更。

对运行中的成员，归档会经过"已结算"再到"已归档"两步。整个过程在界面上表现为按钮"处理中…"，完成后状态点变色。

对"已创建"或"已归档"的成员执行"归档"会直接被拒绝，因为前者还没开始、后者已经归档了。

---

## 6. 成员的工作目录

- 创建时不指定，成员用团队默认工作区。
- 创建时指定了，用指定的。
- 成员**第一次进入运行中之后**，工作目录锁定，不能更改。
- 需要同一角色在另一个目录工作，再创建一个成员。

---

## 7. PilotDeck 差异：Teammate 的只读聊天

点击成员行的 **查看聊天**，打开该 Teammate 的只读聊天视图。视图显示已经落盘的历史和当前的流式输出，并可在浏览器刷新、直接 URL 打开或 WebSocket 重连后恢复到同一个 Team 运行段和成员。

此视图不显示输入框、发送按钮、模型选择、停止、重命名、分叉、编辑或普通会话权限操作，也不会创建新的聊天或调用模型。需要向成员提供新任务或协调消息时，仍由 Leader 使用团队工具；用户也可以回到根会话向 Leader 提出要求，不在只读聊天中直接输入。

Teammate 的权限询问、向用户提问和退出 Plan 模式的授权请求不通过成员聊天转交 Leader，而是直接出现在团队交互面板。处理结果和历史状态保留在面板中。

## 8. 多团队与重启

### 8.1 多个团队

- 一台机器上可以有多个团队，每个团队是一个独立的 Leader 会话。
- 成员只属于创建它的那个团队，不能跨团队移动。

### 8.2 重启后

- 所有成员及其状态、历史都在。
- 成员不会自动恢复运行。"运行中"的成员重启后仍显示运行中，但实际上需要 Leader 再给它发任务才会继续。
- 在团队视图的零状态（还没打开任何团队时）可以看到"已持久化的团队"列表，每行显示：团队标识、蓝图名和版本、默认工作区（没有时显示"（无默认工作区）"）、`N 名成员`、创建时间，以及"以 Team 模式打开 / 回到 Leader"和"以普通模式打开"两个按钮。

## 9. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 点"+"创建成员失败，提示配额超限 | 蓝图 `quotas` 限制。归档或处置一些成员可以释放"并发"配额，但"累计总数"配额不会回收 |
| PilotDeck 查看聊天没有内容 | 成员还没有产生 transcript；只读视图显示空状态，不会创建新会话 |
| 给"已归档"成员发任务找不到按钮 | 先点"恢复"，回到"已结算"后才有"恢复…"（发任务） |
| 成员状态很久不更新 | 团队视图每 3 秒自动刷新一次，也可以手动点顶部"刷新团队视图"。已知存在偶发滞后，刷新页面可解决 |
| 想换成员的工作目录 | 运行过的成员不能换。新建一个同角色成员并指定目录 |
| 处置后想找回成员 | 不能恢复。但它的会话历史还在，可以从团队事件或时间线里点进去查看 |
