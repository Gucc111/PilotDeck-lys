# Team 模式功能详解 · 模块 5：团队视图与监控

> 本文保留 2026-10-14 的 **DSH 参考产品调研**，不是 PilotDeck 的已实现功能清单。除明确标注“PilotDeck”的段落外，文中的“当前版本”、工具、按钮和限制均指调研时的 DSH。PilotDeck 使用说明见 [docs/team-mode.md](../../team-mode.md)。
> 上级文档：[Team 模式用户功能清单](../team-mode-user-features.md)

> **PilotDeck 当前实现边界**：团队详情负责展示成员配置和运行状态；团队交互是与之并列的独立入口，专门承载 Teammate 直接发给用户的权限询问、用户问题和 Plan 授权。成员聊天只读，不提供普通会话输入。

---

## 1. 这个模块解决什么问题

一个团队跑起来后，人类需要随时回答：现在谁在干活、干到哪了、有没有卡住、有没有等我批的事、过去发生了什么。本模块说明团队视图的每个面板显示什么、能点什么、数据多久更新一次。

---

## 2. PilotDeck 入口

| 入口 | 位置 | 显示条件 |
| --- | --- | --- |
| **团队详情** | 输入区附近的 Team 入口 | 显示 Team 配置、成员、任务和运行状态 |
| **团队交互** | 与“团队详情”并列 | 显示 Teammate 发给用户的待处理和历史交互 |
| **DSH 参考：团队**标签页 | 会话窗口顶部，和"对话"、"轨迹"并列 | 普通会话显示零状态（见第 9 节） |
| **DSH 参考：Team 状态条** | 输入框上方 | 只在团队会话（Leader 或成员的窗口）出现 |

Teammate 的“查看聊天”打开只读成员视图，显示其历史和流式输出，不显示输入框、模型选择、停止、重命名、分叉或编辑控件。团队详情和团队交互入口仍属于根会话，不创建新的成员聊天。

---

## 3. 团队视图整体布局

从上到下固定顺序：

```
┌ 顶部状态栏（刷新按钮、更新状态、错误提示）
├ 损坏记录提示条（有损坏记录时才出现）
├ 时间线
├ 成员组
├ 治理（兼容性 / 策略 / 生效配置 / 治理介入 + 权限管理）
├ 活动与进度
└ 团队事件
```

各区标题：时间线、成员组、治理、活动与进度、团队事件。

---

## 4. 顶部状态栏

| 元素 | 显示时机 | 内容 |
| --- | --- | --- |
| 刷新团队视图 | 始终 | 按钮。点击立即拉取最新数据，同时刷新团队事件列表 |
| 正在更新… | 刷新进行中 | 文字标记 |
| 更新失败，当前显示上次成功的数据 — 错误码: 原因 | 刷新失败但之前有数据 | 保留旧数据，加提示 |
| 团队归属刷新失败，当前显示上次成功的数据 | 无法确认当前会话属于哪个团队，但之前确认过 | 保留旧数据，加提示 |

## 5. 时间线

### 5.1 显示什么

一张甘特图。每个成员一行（Leader 不占行），每一段运行时间一根横杠。

- 左侧每行显示成员名和一个色块，当前会话对应的成员高亮。
- 同一成员多次"运行中 → 已结算 → 运行中"会在同一行出现多根横杠。
- 归档或处置成员不会删掉它的历史横杠。
- 还在运行的横杠右端随时间延伸，每秒刷新。
- 时间轴刻度自动选择合适间隔。
- 没有任何任务记录时显示"暂无委派记录"。

### 5.2 怎么操作

| 操作 | 效果 |
| --- | --- |
| 鼠标滚轮 | 以鼠标位置为中心缩放，最小可缩到 1 秒 |
| 按住拖动 | 左右平移 |
| 双击 | 重置到默认视野 |
| 鼠标悬停横杠 | 约 0.2 秒后显示：成员名、开始到结束时间、持续时长、还在跑的标"进行中" |
| 点击横杠 | 打开该成员的会话窗口 |
| ← / → | 左右平移 10%，按住 Shift 平移 50% |
| + 或 = | 放大 |
| - 或 _ | 缩小 |
| 0 或 Esc | 重置 |
| 右键 | 无菜单 |

键盘操作需要先点击时间线获得焦点。屏幕阅读器可读到的说明："团队委派时间线：滚轮缩放，拖拽平移，方向键平移，按 0 复位"。

## 6. 成员组

详见模块 2 第 4 节。要点：

- Leader 组固定在最上面，显示 `N 活跃`，带"以 Team 模式打开 / 回到 Leader"和"以普通模式打开"两个按钮以及当前模式徽章。
- 每个角色模板一组，组标题显示 `N 活跃`，右侧"+"创建成员。模板下没有成员显示"尚无实例"。
- 每个成员一行：查看聊天按钮、状态点和状态词、当前动作（无则"暂无动作"）、`N 项待处理`徽章、操作按钮、错误提示。徽章统计 Teammate 人类交互，点击团队交互入口处理。

## 7. 治理

详见模块 4。四张卡片：

| 卡片 | 看什么 | 能做什么 |
| --- | --- | --- |
| 兼容性 | 状态徽章、警告/致命/已确认计数、代数、最后探测时间 | 审查（读取最新结果）、重新检查 |
| 策略 [当前模式] | 当前治理模式 | 审查（展开能力编辑行）、提交切换 |
| 生效配置 | 每个成员的模型、工作区、权限汇总、自主范围，各带来源和状态词 | 查看覆盖、设置覆盖、重置覆盖 |
| 治理介入 | 待审批、治理警告、错误；权限管理子卡片 | 允许、拒绝、升级、确认（按钮由服务端决定） |

## 8. 活动与进度

### 8.1 显示什么

每条进度记录一行：

| 元素 | 内容 |
| --- | --- |
| 状态点 | 进行中 🔵 / 已完成 🟢 / 受阻 🔴 |
| 主题 | 这项工作叫什么（没有主题时退而显示当前动作或摘要） |
| 状态词 | 进行中 / 已完成 / 受阻 |
| 负责人 | `负责人 成员名` |
| 摘要 | 可选的一句话说明 |

没有记录时显示"暂无活动进度"。

### 8.2 数据来源

来自成员或 Leader 调用进度工具写下的记录（模块 3 第 6 节）。这个面板只展示，不可点击，不会触发任何动作。

## 9. 团队事件

### 9.1 这是什么

团队内发生过的所有事的完整流水：谁创建了成员、谁给谁派了任务、谁发了消息、谁申请了什么审批、谁批了、治理模式怎么切的、兼容性怎么变的、进度怎么报的。这是团队的"审计日志"。

它**不是**把各个会话的对话记录合并起来。每个会话自己的对话在它的"对话"和"轨迹"标签页里。

**PilotDeck 差异**：Teammate 面向人类的权限询问、问题和 Plan 授权以交互记录保存在团队交互面板；它们不再伪装成 Leader 的控制事件，也不要求用户到 Leader 聊天里寻找卡片。普通成员协作消息、任务、治理和兼容性变化仍记录在团队事件中。

### 9.2 顶部控制栏

| 控件 | 选项 / 作用 |
| --- | --- |
| 类别筛选 | 全部 / 团队 / 成员 / 生命周期 / 消息 / 控制 / 策略 / 兼容 / 进度 |
| 成员筛选 | 按某个成员或某个角色模板筛选 |
| 加载更早 | 默认显示最近 200 条，每点一次多显示 200 条 |
| 还有 N 条事件未加载 | 提示还有多少没显示 |
| 重试 | 加载失败时出现 |

### 9.3 每一行显示什么

一行一条，从左到右：

| 元素 | 内容 |
| --- | --- |
| 状态点 | 按事件类型：待确认的治理事件琥珀色、已处理绿色、损坏记录红色、进度按进度值着色 |
| 时间 | 事件发生时刻 |
| 类型 | 工作准入 / 成员创建 / 生命周期 / 消息 / 控制请求 / 控制裁决 / 裁决消费 / 进度 / 活动开始 / 活动结束 / 策略变更 / 治理提案 / 控制升级。不认识的类型显示原始名称 |
| 参与者 | 谁做的（成员名，或"人工"） |
| 摘要 | 一句话。鼠标悬停看完整内容 |
| 状态标记 | 视类型而定：治理事件显示"等待确认"或"损坏 · 不可处理"；进度显示进度值 |

点击一行，跳转到相关的会话窗口（例如点一条"成员创建"跳到那个成员的窗口）。没有可跳转目标的行不可点击。

审批被系统硬性限制拦住的情况分两行显示："团队裁决：已允许" / "执行：被托管策略阻止"。

### 9.4 普通团队控制事件详情

DSH 的治理控制事件行下方可以展开详情面板。下表保留 DSH 的详情字段；PilotDeck 的工具权限询问、用户问题和 Plan 授权在独立团队交互面板处理，不实现此治理控制面板：

| 字段 | 内容 |
| --- | --- |
| 请求方 | 哪个成员，或"人工" |
| 请求类型 | 治理警告 / 范围变更 / 兼容性控制 |
| 请求操作 | 要做什么 |
| 工具 | 涉及哪个工具 |
| 原因 | 成员给出的理由 |
| 创建时间 | |
| 当前状态 | 等待确认，或损坏 · 不可处理 |
| 请求权限 | 需要哪一级批 |
| 控制对象 | 针对哪个成员 / 模板 / 整个团队 |
| 请求编号 | |
| 渲染模式 | 标准 / 兼容旧格式 / 恢复模式 / 对象不支持 / 记录损坏 |
| 审阅载荷摘要 | 参数的校验值（如有） |
| 审阅载荷 | 完整参数，原文显示（如有） |

DSH 面板底部按事件提供允许、拒绝、升级、确认等治理操作。PilotDeck 的允许/拒绝、回答和 Plan 授权按钮位于团队交互面板，不提供 DSH 治理操作。

- 参数不完整时显示缺失字段并禁用依赖该参数的操作。
- 记录损坏时操作按钮禁用。
- 需要人类确认的治理警告显示“确认”，不代替 Teammate 交互响应。

### 9.5 空态与错误

| 情况 | 显示 |
| --- | --- |
| 正在加载 | 正在加载团队事件… |
| 没有事件 | 暂无团队事件 |
| 加载失败 | 事件加载失败：原因 + 重试按钮 |

## 10. Team 状态条（输入框上方）

### 10.1 折叠态

一行："团队 · N 运行中 · M 待处理"。为零的项不显示。右侧一个展开/收起箭头。

### 10.2 展开态

两个列表：

| 列表 | 内容 | 空态 |
| --- | --- | --- |
| 成员 | 每个成员：名字 + 状态点 | 暂无成员状态 |
| 活动 | 每条进度：主题 + 状态点 + 状态词 | 暂无活动进度 |

状态条只做速览，没有任何操作按钮。左侧的"团队"文字按钮目前点击无效果（已知问题），要打开团队视图请直接点顶部的"团队"标签页。

### 10.3 PilotDeck 差异：团队交互面板

团队交互入口与团队详情并列，按钮显示尚未处理的数量。面板只列 Teammate 卡片；每张卡片显示显示名、角色、当前状态和 **查看聊天**，不重复列出模型、工作区或能力配置。

卡片下有三个可展开区域：

1. **工具调用权限询问**：Teammate 的工具调用需要用户允许或拒绝时出现；
2. **向用户提问**：`ask_user_question` 的问题和选项出现；
3. **Plan 授权执行**：`exit_plan_mode` 的计划详情以及批准/拒绝执行出现。

每行仅展示通知摘要、创建时间和状态。点击待处理行后复用普通会话的对应交互卡片。处理成功后记录保留在历史区域；请求本身已终止的失败也保留记录。网络或响应提交失败时，记录仍保持待处理并显示可重试错误。历史区域显示允许、拒绝、已回答、已取消、已批准、已拒绝、已过期或失败。面板刷新、直接 URL 打开和 WebSocket 重连都从服务端交互记录恢复；错误 Team、成员或代次的响应不能改变记录。

## 11. 数据更新机制

| 机制 | 说明 |
| --- | --- |
| 自动轮询 | 每 3 秒检查一次是否有变化，有变化才拉取完整数据 |
| 标签页隐藏时 | 暂停轮询，切回来恢复 |
| 手动刷新 | 顶部"刷新团队视图"，强制拉取并刷新事件列表 |
| 操作后 | 任何成员操作、治理操作成功后自动拉取一次 |
| 断线重连 | 连接恢复后自动拉取一次 |

界面永远显示服务端确认过的状态，不做"先改界面再同步"。所以点了按钮后状态词可能要过一两秒才变。

已知问题：偶发状态滞后需要刷新页面；多个团队共存时非第一个团队的事件列表可能少显示一部分；事件列表很长时翻找待裁决项较慢。

## 12. 零状态：普通会话里的团队标签页

普通会话（不属于任何团队）打开"团队"标签页看到的内容：

### 12.1 状态行

根据当前情况显示一条：

| 显示 | 含义 |
| --- | --- |
| 已确认当前会话未加入团队 | 这是普通会话 |
| 正在读取团队归属… | 正在确认 |
| 正在加载团队状态… | 已确认属于团队，正在加载 |
| 团队归属读取失败 — 错误码: 原因 | 服务端出错 |
| 无法读取团队归属，等待连接恢复 | 断线 |
| 团队信息尚未成功加载，正在重试 | 重连中 |
| 当前会话未能关联到团队（可能是普通会话） | 关联失败 |
| 团队信息加载失败 | 加载失败 |

### 12.2 已持久化的团队

列出这台机器上所有已创建的团队，每行：

| 元素 | 内容 |
| --- | --- |
| 团队标识 | Leader 会话编号 |
| 蓝图 | `蓝图标识@修订号` |
| 默认工作区 | 路径，没有时显示"（无默认工作区）" |
| 成员数 | `N 名成员` |
| 创建时间 | |
| 以 Team 模式打开 / 回到 Leader | 以完整团队功能打开这个团队的 Leader 会话 |
| 以普通模式打开 | 把 Leader 会话当普通会话打开，不加载团队功能 |

每行单独显示操作进行中和失败提示。列表每 3 秒自动刷新。读取失败显示"读取持久化团队失败：原因"。

### 12.3 从此处开始团队

一个按钮，点击在当前位置展开创建面板，并带上当前会话作为上下文交接源。详见模块 1 第 3 节。

### 12.4 刷新按钮

"刷新团队视图"，手动重新读取归属和团队列表。

## 13. 旧版团队会话

如果打开的是由更早版本的团队功能创建的会话，团队标签页显示一个只读说明：

```
本会话由旧版 Team 实现创建。
Team vNext 不会将其作为 vNext 团队恢复或变更。
历史 Chat 与 Trajectory 仍可访问。
```

下方"已解码的旧版团队摘要（只读）"：团队标识、Leader 会话、`N 名花名册成员 · N 个扫描会话`、成员列表。

没有任何操作按钮。这类会话不能恢复为新版团队，也不会被自动迁移；它的对话记录和执行轨迹照常可看。

读取旧版信息失败时显示"旧版团队检查失败：原因"，并回到普通零状态。

## 14. 设置页

设置页有一个"团队"区段，标题"团队成员配置"。当前只有静态说明文字，没有可编辑项。说明文字描述的是旧版的配置方式（Markdown 文件），与当前蓝图流程不一致，可忽略。

## 15. 看什么去哪里：速查

| 想知道 | 看哪里 |
| --- | --- |
| 现在几个成员在跑、几件事等我批 | 输入框上方状态条 |
| 每个成员的状态和当前动作 | 成员组 |
| 成员什么时候开始、跑了多久 | 时间线 |
| 任务进展到哪一步 | 活动与进度 |
| 有没有等我处理的 Teammate 请求 | 团队交互面板（按成员查看三个交互区域） |
| 某个成员用的什么模型、有什么权限 | 治理 → 生效配置；治理 → 治理介入 → 权限管理 |
| 环境是否还满足团队要求 | 治理 → 兼容性 |
| 过去发生了什么 | 团队事件 |
| 某个 Teammate 的流式聊天 | 团队交互面板 → 查看聊天（只读） |
| 这台机器上有哪些团队 | 任意普通会话的团队标签页 → 已持久化的团队 |

PilotDeck 本次不实现本篇 DSH 的 Gantt 时间线、动态成员操作、治理面板和团队事件过滤器。当前入口与内容以第 2 节、第 10.3 节和 [PilotDeck 使用说明](../../team-mode.md) 为准。
