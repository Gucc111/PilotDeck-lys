# Team 模式功能详解 · 模块 6：团队生命周期与恢复

> 本文保留 2026-10-14 的 **DSH 参考产品调研**，不是 PilotDeck 的已实现功能清单。除明确标注“PilotDeck”的段落外，文中的“当前版本”、工具、按钮和限制均指调研时的 DSH。PilotDeck 使用说明见 [docs/team-mode.md](../../team-mode.md)。
> 上级文档：[Team 模式用户功能清单](../team-mode-user-features.md)

> **PilotDeck 当前实现边界**：Teammate 人类交互请求使用独立的持久化 interaction ledger。浏览器刷新和 WebSocket 重连恢复 pending 与已处理记录；Gateway 重启使仍 pending 的请求过期，保留历史但不能继续点击执行。Teammate 聊天通过只读流式视图恢复，不创建新的聊天 session。

---

## 1. 这个模块解决什么问题

团队不是一次性的。创建之后可能关掉浏览器、重启服务、过几天再回来。本模块说明：团队和成员的哪些东西会保留、重启后怎么回到团队、哪些事情需要人手动做、以及什么情况下团队会"暂停接单"。

---

## 2. 什么会保留

关闭页面、重启服务、重启机器之后，以下内容全部保留：

| 内容 | 说明 |
| --- | --- |
| 团队本身 | 绑定的蓝图版本、默认工作区、创建时间 |
| 所有成员 | 实例编号、标签、分组、工作区、状态（已创建 / 运行中 / 已结算 / 已归档 / 已处置） |
| 每个成员的会话 | 完整对话记录和执行轨迹 |
| Leader 的会话 | 同上 |
| 团队事件 | 全部历史，一条不少 |
| DSH 审批记录 | 控制请求历史保留；PilotDeck 的 pending/过期规则单独见第 3.5 节 |
| 权限变更 | Leader 或人类做过的所有权限调整 |
| 能力覆盖 | 人类设置过的模型、工具、技能、外部服务覆盖 |
| 治理模式 | 当前切到哪个模式 |
| 兼容性确认 | 创建时确认过的降级 |
| 已派任务的结果 | 已完成任务的结果可以继续用 `team_collect` 查 |

一句话：**所有"配置"和"历史"都在，只有"正在运行的进程"不在。**

## 3. 重启后怎么回到团队

### 3.1 找到团队

打开任意一个普通会话，点"团队"标签页，零状态下有"已持久化的团队"列表。每行显示团队标识、蓝图和版本、默认工作区、成员数、创建时间。

或者直接从侧边栏点开原来的 Leader 会话。

### 3.2 两种打开方式

| 按钮 | 效果 | 什么时候用 |
| --- | --- | --- |
| **以 Team 模式打开 / 回到 Leader** | 启动 Leader 的 AI 进程，加载团队工具和人设，进入完整团队功能 | 正常继续使用团队 |
| **以普通模式打开** | 把 Leader 会话当成普通会话打开，不启动团队功能，不加载团队工具 | 只想翻翻历史、或者团队功能出了问题想绕开它 |

两个按钮在零状态的团队列表里有，在团队视图的 Leader 组里也有。

"以普通模式打开"是一次性的：下次再打开这个会话，仍然会按团队会话处理。

### 3.3 成员不会自动醒来

重启后：

- 成员的状态显示和重启前一样（包括"运行中"）。
- 但没有任何成员的 AI 进程在跑。
- 给成员发新任务（Leader 调工具或人类在界面点"发送任务"）时，系统自动唤醒它，接上原来的对话上下文继续。用户不需要手动"启动"成员。
- 一个重启前显示"运行中"的成员，如果它的任务在重启前没做完，这个任务不会自动继续。Leader 用 `team_collect` 查该任务会看到"运行中"，可以用同一个令牌重新派一次来续接。

### 3.4 通知不会补发

重启前没来得及送到 Leader 的两类通知，重启后不会补发：

| 通知 | 重启后怎么找回 |
| --- | --- |
| 任务完成通知 | Leader 用 `team_collect` 查自己派过的任务令牌 |
| DSH 控制通知 | Leader 用团队工具查询；这条恢复方式不适用于 PilotDeck 人类交互 |

DSH 重启后可以让 Leader 检查已完成任务和待批审批。PilotDeck 只通过交互 ledger 恢复或失效 Teammate 的人类请求，不要求 Leader 找回或裁决。

### 3.5 PilotDeck 差异：Teammate 交互请求的恢复

Teammate 的工具权限询问、`ask_user_question` 和 `exit_plan_mode` 不依赖 Leader 通知。请求产生时先写入 interaction ledger，再通过专用事件送达团队交互面板。面板按 Teammate 显示待处理和历史记录，点击后复用对应的普通交互卡片。

- 浏览器刷新或 WebSocket 断线：重新读取 ledger，pending 行仍可处理，已处理记录仍可追溯。
- Gateway 重启：内部等待句柄已经失效的 pending 行标为“已过期”，保留请求快照和错误原因，禁止再次提交或重放。
- Team 停止：未处理行标为“已取消”，保留历史；同一个请求 ID 的重复响应只返回已有结果。
- 响应必须带原 Team、运行段、Teammate 和请求代次。错误归属不会影响原请求。

Teammate 的 **查看聊天** 只读视图读取同一运行段的成员 transcript，并以流式事件增量更新。它没有输入框、发送、停止、模型选择、分叉或编辑操作，刷新不会启动新回合。

## 4. 团队什么时候会"暂停接单"

团队有一个总开关，决定能不能接收新任务。关闭时已经在跑的任务继续跑完，但新的派任务、创建成员、跟进都会被拒。

### 4.1 触发原因

| 原因 | 表现 | 怎么恢复 |
| --- | --- | --- |
| 环境里缺了蓝图要求的能力（例如外部服务断了） | 治理 → 兼容性显示"⚠ 需要处理"或"✕ 结构性错误" | 修好环境，点"重新检查" |
| 蓝图两个权限上限字段自相矛盾 | 治理 → 治理介入出现一条警告，Leader 不启动 | 点"确认"后 Leader 启动；或改蓝图新建团队 |
| 团队数据损坏，成员绑定自相矛盾 | 团队视图报错，新任务被拒 | 需要技术人员检查数据 |

### 4.2 不会触发暂停的情况

- 审批记录里有损坏条目：只显示提示条，不影响接单。
- 某个成员卡住了：只影响那个成员。
- 可选能力缺失且已确认降级：正常接单，状态显示"⚠ 降级"。

## 5. 团队的"结束"

当前版本没有"归档团队"或"删除团队"的操作。一个团队不用了就是：

1. 把成员逐个归档或处置（可选，释放并发配额）。
2. 不再打开它的 Leader 会话。

团队和它的全部历史会一直保留在"已持久化的团队"列表里。

---

## 6. 复制一个团队

对 Leader 会话使用系统的"分叉会话"功能，会得到一个新团队：

- 用同一份蓝图（同一个版本）。
- 继承 Leader 的对话历史。
- **成员列表是空的**，原团队的成员不会复制过来。
- 是独立的团队，和原团队互不影响。

**PilotDeck 差异**：Teammate 只读聊天视图不支持分叉、输入或普通会话操作；它只是当前 Team 运行段 transcript 的展示入口。需要新运行或新 Team 时，从根会话按 Team 配置流程创建，不能从成员只读视图复制执行上下文。

---

## 7. 蓝图更新对已有团队的影响

| 操作 | 对已有团队 | 对新建团队 |
| --- | --- | --- |
| 新增一个更高修订号的蓝图文件 | 无影响，继续用原来的版本 | 创建时可以选新版本 |
| 原地修改已有团队正在用的蓝图文件 | 无影响，团队用的是创建时冻结的副本。但再派任务时可能报"内容不一致"错误 | 用修改后的内容 |
| 删除蓝图文件 | 无影响 | 列表里消失，不能再用它建队 |
| 插件升级带来新工具 | 无影响，团队的工具列表在创建时冻结 | 新团队可以用 |

想让一个团队用上新设计，只能用新蓝图再建一个团队。

---

## 8. 旧版团队

更早版本的团队功能创建的会话，在当前版本里是只读的：

- 可以打开，可以看对话记录和执行轨迹。
- 团队标签页显示旧版团队的摘要（团队标识、Leader、成员名单）。
- 不能恢复、不能派任务、不能创建成员、不能改任何设置。
- 不会被自动转换成新版团队。

要继续同样的工作，用"从此处开始团队"基于这个会话新建一个团队，把上下文摘要带过去。

## 9. 一张表看懂重启前后

| | 重启前 | 重启后 |
| --- | --- | --- |
| 团队存在吗 | 是 | 是 |
| 成员和状态 | 在 | 在，状态不变 |
| 成员在跑吗 | 可能在跑 | 都没在跑，发新任务时自动醒 |
| 未完成的任务 | 在跑 | 停了，`team_collect` 显示运行中，同令牌重派可续接 |
| PilotDeck 人类交互（对照） | pending | 浏览器刷新可继续处理；Gateway 重启后标记过期，历史保留 |
| 已派任务的通知 | 会送到 Leader | 不补发，Leader 自己查 |
| 历史和事件 | 在 | 在 |
| 权限和覆盖 | 在 | 在 |
| 怎么回去 | 直接用 | 点"以 Team 模式打开" |

PilotDeck 不采用 DSH 的“重启后同令牌重派续接”或“分叉 Leader 生成 Team”行为。PilotDeck 的任务和交互恢复、停止边界以 [使用说明](../../team-mode.md) 为准。
