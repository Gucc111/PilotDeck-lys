使用 Codex 内置浏览器打开真实 PilotDeck Web UI，在普通会话中向真实模型发送需求。
用户输入只描述团队类型、工作内容，可描述成员的大致职责；不指定角色 system prompt、API 字段、模型 ID、保存或校验步骤。
Agent 应自行发现内置 skill、设计配置、通过 Gateway 保存并回读，在 Teams 页面可以看到结果。

服务：Vite `127.0.0.1:5173`、Express `3001`、Gateway `18789`。
使用独立 `PILOT_HOME=/tmp/pilotdeck-team-skill-e2e-20261104/home` 和独立数据库。
普通会话使用默认权限，对必要的本地命令点选一次允许，不持久扩大权限。
有效测试模型为 `llmcenter-openai/deepseek-v4.1-flash`。
没有注册项目、没有启动 Team 执行；本次验收范围为配置创建、编辑和 UI 持久化展示。

Agent 隐式读取 `pilotdeck-team-config`，自行生成角色提示词和能力，保存了 1 位 Leader、3 位 Teammate 及“资料审阅团队”。
Team ID：`cd687338-5de6-4da5-8e00-e19e272d2e8c`。
成员：审阅主编、事实核查员、结构审阅员、措辞编辑。

该轮不记为完整通过：Agent 读配置文件发现模型，选择了已在服务端退役的默认模型；创建后又在没有注册项目的情况下反复猜测 projectKey 运行检查，最终人工停止。
此前精确指定技术参数的输入已弃作验收标准。模型调用的“Opus 4.6 已不可用”和“deepseek-v4.1-flash-mb 对用户不可见”属于真实服务失败，不算成功执行。

## 本次修正

- helper 协议版本与真实 Gateway 对齐为 `1.1`，使用允许的客户端名 `cli`，连接关闭时返回原因。
- 将 skill 的 description 改为单行，兼容实际运行时的前置信息解析器；避免隐式选择只看到 `>-`。
- 增加只读 `models`、`projects` helper 动作，分别调用 `model_catalog_list`、`list_projects`，无需读取含凭据的配置或猜测内部目录。
- 明确由 Agent 根据工作目的设计成员、提示词、交付物和协作方式，不要求用户填写底层参数。
- 新角色默认采用目录返回的默认模型、继承团队工作区、默认权限；能力从 inventory 中挑选。
- 普通会话未选项目时，保存并回读即可结束；不为了配置任务注册项目或反复猜测项目运行检查。
- 编辑保留对象 ID，使用完整配置保存，保留用户未要求改变的字段。
- 明确 runtime_probe 只检查本地配置，不代表远端模型可用或实际团队任务已完成。

测试环境另将默认模型调整为已经实际完成工具调用的 deepseek-v4.1-flash。这是独立测试环境准备，不是用户提示词的技术引导。

| 角色 | 名称 | 工作范围 |
| --- | --- | --- |
