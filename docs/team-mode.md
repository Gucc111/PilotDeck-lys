# Team：配置与当前会话协作

Team 由一位 Leader 和至少一位 Teammate 组成。先在侧栏的 **团队 / Teams** 页面管理角色和团队；使用时，在聊天输入框右下角的模型下拉列表中选择 Team 的显示名称。当前会话由这个 Team 的 Leader 接手，用户继续在同一个聊天中提问。

选择 Team 不调用模型。新会话第一次发送时才建立运行记录；已有会话保留原来的 URL、历史和输入草稿。不会为成员创建侧栏聊天，也没有额外的“开始团队对话”流程。

`docs/research/team-mode/` 是 DSH 参考产品调研。本文描述 PilotDeck 的实现，两者的功能边界不同。

## 使用例子

配置一个“发布评审团队”：

1. 从侧栏打开 **团队 / Teams**。在 **Leaders** 新建“发布负责人”，填写职责提示词、模型、工作区和能力。
2. 在 **Teammates** 新建“代码审查员”和“测试员”。两类角色支持相同的配置字段。
3. 新建“发布评审团队”，选中一位 Leader 和两位 Teammate，保存。
4. 回到项目聊天，在输入框右下角下拉列表的 **团队** 分组选“发布评审团队”。查看工作区和兼容性检查；有可选能力缺失时明确确认后继续。
5. 输入“检查本次发布是否可以上线”。Leader 可以异步分配审查和测试任务；不同成员并行，同一成员的工作串行。简单问题也可以由 Leader 直接回答。
6. 测试员可以直接发消息询问代码审查员。代码审查员忙时在下一次模型请求收到，空闲时开始新一轮。Leader 可以查询全队通信。
7. 每轮成员结果先保存，再由程序通知 Leader 查询。Leader 读取指定成员、指定轮次的结果并在原会话中汇总。轮次结束不等于整个工作已经完成。

如何分工由 Leader 根据用户要求决定。创建团队不会把每条用户输入广播给所有成员。

## Team 人类交互面板

Team 的执行者分为 Leader 和 Teammate。Teammate 需要人类决定时，不经过 Leader：

- 工具调用命中询问规则时，权限请求直接进入用户的 **团队交互** 面板。
- Teammate 调用 `ask_user_question` 时，问题和选项直接进入该面板。
- Teammate 调用 `exit_plan_mode` 时，计划详情和“批准执行 / 拒绝执行”也直接进入该面板。

输入区附近的 **团队交互** 入口与 **团队详情** 并列。面板增加 Leader 收件板块，各成员都有“消息”，按接收者展示发送者、时间、截断正文和状态，可展开全文。Leader 的权限、问答、Plan 审批仍使用主聊天卡片；Teammate 保留“工具调用权限询问”“向用户提问”“Plan 授权执行”三个区域。模型、工作区、工具、技能和 MCP 等配置继续在团队详情中查看，详情中不再展示任务和通信记录。

列表中的一行只显示通知摘要、时间和状态。点击后打开普通会话使用的交互卡片；处理完成后仍保留在历史中，并标记允许、拒绝、已回答、已取消、已批准、已拒绝、已过期或失败。响应提交失败时仍保持待处理并显示错误；刷新和重连以服务端保存的交互记录为准，不能因为页面刷新而丢失待处理事项。停止 Team 后未处理记录显示“已取消”，Gateway 重启后失效等待显示“已过期”，均保留历史但不能继续执行。

点击 Teammate 的 **查看聊天** 打开该成员的只读聊天视图。视图展示历史和实时流式输出，不显示输入框、模型选择、发送、停止、重命名、分叉或编辑控件，也不会创建新的聊天或调用模型。

## 配置库

| 对象 | 可配置内容 |
| --- | --- |
| Leader / Teammate | 显示名称、描述、系统提示词、模型参数、工作区、工具、技能、MCP、可选能力声明、执行审批方式 |
| Team | 显示名称、描述、团队说明、默认工作区、一位 Leader 和至少一位 Teammate |

ID 由程序随机生成。配置库每个 ID 只保留当前配置，不记录角色或 Team 的历史修订。

角色工作区可以继承本次 Team 的项目，也可以固定为一个已登记项目。已有项目会话保持当前项目；固定 Leader 与其冲突时阻断选择。通用会话可以选择已登记的执行项目，原历史仍保存在通用会话的存储位置。固定 Teammate 可在它配置的项目执行。

编辑角色直接替换当前配置；引用该角色的 Team 按 ID 自动使用最新配置。Fork 角色生成独立角色；Fork Team 生成独立 Team。Fork 不复制文件、历史、凭证或审批记录。删除被 Team 引用的角色会被拒绝，避免产生悬空引用。

进入 Team 模式时固定 Team、角色、初始模型、工作区和能力快照。配置库后续编辑不会悄悄改变运行中的会话；普通模型选择也不会覆盖 Team 角色模型。Team 选择不成为新普通会话的全局默认值。

## 消息与查询

| 工具 | 作用 |
| --- | --- |
| `team_send_message({recipientId,text})` | 可靠保存后返回消息编号和 queued，不等待对方启动、回复或执行结束 |
| `team_inspect` | 按明确视图查询成员状态、轮次或通信，不启动成员 |

`team_inspect` 默认 `view:"overview"` 返回全队名单、角色、状态、未消费数量和最新轮次，不含结果正文。`view:"turns"` 需要 `participantId`，返回轮次时间、结束原因和注入记录；Leader 可以查看成员，Teammate 仅自己。`view:"turn"` 必须同时指定 `participantId` 和 `turnId`，只有 Leader 能读取指定 Teammate 的本轮正式结果。`view:"messages"` 分页读取通信，可按成员过滤；Leader 可查全队，Teammate 只能查自己收发的消息。消息正文仅在实际发送模型后可查询；未发送、已失效和发送状态不确定的记录只返回编号、双方和状态等信息，防止正文通过查询结果提前进入模型历史。界面仍显示完整收件内容。旧委派、追问、收集、转发和等待工具不再提供，也没有别名。

工具的发送身份来自服务端运行上下文，模型不能指定自己是另一个成员。目标必须属于当前 Team，且不能发给自己。成员只获得收到的消息和自己的历史，不自动读取 Leader 或其他成员历史。

模型查询通信记录时，尚未消费、已失效或发送情况不确定的消息只返回编号、双方和状态等信息，不返回正文；只有已实际发送模型请求的消息可查询正文。这样不能通过查询工具提前读到待发送内容，也不会在用户删除后从工具结果或摘要中重新出现。人类收件面板仍能查看原文。

Leader 可以发送工作要求、询问和补充要求。Teammate 使用同一工具沟通、询问、补充信息，最终工作成果写入本轮最终回答。程序保存正式结果后发送固定通知，让 Leader 调用 `team_inspect` 查询；通知不含成果正文。工具描述和提示词说明这个约定，不按正文猜测并拦截消息。发送消息不会授予文件、工具或审批权限。

成员的模型执行上下文保存在内部运行目录，不是可单独发送消息的聊天。工具能力通过角色专属注册表执行；技能读取和提示列表使用同一允许集合；MCP 只连接选择的服务器。普通 `agent`、共享 `task_*` 和 Always-On 专用工具不作为 Team 基础能力提供。文件及命令仍使用 PilotDeck 的现有审批机制，这些能力设置不是操作系统沙箱。

Teammate 的权限询问、`ask_user_question` 和 `exit_plan_mode` 不属于普通协调消息。它们先写入 Team 运行段的持久化人类交互记录，再通过专用事件送达用户；Leader 不接收、转发或裁决这些请求。交互响应必须绑定原 Team、运行段、Teammate 和请求代次；重复响应只返回已有结果，错误归属不能消费请求。

## 执行、停止和恢复

所有方向使用相同规则：空闲收件启动一轮，忙时加入当前轮下一次合适的模型请求。从环境准备到执行退出，同一成员只运行一个 Loop；Leader 人工输入和内部续轮共用这个限制。每个处理边界一次取出当时全部有效消息，之后到达的进入下一批。没有累计自动续轮上限，保留单轮步数限制和 Abort。

待发正文保留在消息记录，既不进入压缩摘要，也不进入辅助模型请求。为完整批次预留空间后再压缩旧历史，仍装不下时保留消息并显示错误，不截断、不拆批、不反复空转。队列变化后可以重试。最终请求发送前再次检查删除和失效状态。

只有正文实际放入请求体，并调用 SDK 或网络发送入口后，才记录消费和请求编号。这不代表模型服务端已收到或理解。Leader 空闲收件续轮在上一条最终回答下显示浅灰分隔线；忙时只在当前轮标记注入。Teammate 空闲收件显示整批 user message，忙时以分隔线显示注入内容。实时和历史都按稳定 turnId 分组。

用户可尝试删除成员消息，后端在与实际发送相同的短临界区内判定。删除先完成则移除正文并保留防重投记录；发送先发生则提示“已发送模型请求，无法删除”。当前有效消息删除后，程序向发送者发送固定反馈，要求更换思路或尽快结束并最终回复。系统通知不可删除。发送中崩溃且无法确认时标记“发送情况不确定”，不自动重发，也不能宣称撤回成功。

**停止**作用于整个 Team，包括 Leader、成员、排队消息、通知、自动续作和待发用户输入。界面先显示“正在停止”，实际执行及 MCP 等资源清理结束后才显示“已停止”；等待超过 30 秒仍未退出或清理失败时，保留具体状态和错误，不允许开始新运行。清理失败可重试停止，同一次停止不重复增加运行代次。失效的用户输入保留正文和附件引用，可放回输入框后明确重新发送。停止不能撤销已经发生的文件修改或外部副作用。

**Gateway 重启**使旧运行失效：未结束轮次标记服务中断；尚未消费的消息及程序通知不能再唤醒成员或 Leader，在收件面板保留并显示“已失效，不会发送”。失效成员消息可以删除，但仅清理显示，不反馈、不唤醒原发送者。已保存结果和聊天历史保留。**Gateway 或 Web bridge 重启**都会使 Team 用户排队输入失效，文本与附件引用保留，可以放回输入框后明确重新发送。仅重启 Web bridge 不代表仍在运行的 Gateway 成员已经中断。浏览器刷新或断线不等于服务重启；连接回同一服务是恢复观察，不会重新投递已接纳输入。

只有在没有运行和待处理消息时才允许切换 Team 或普通模式；也可以先停止并等待清理完成。`activationId` 标识所选 Team 运行段，`stopVersion` 标识该运行段的代次。轮次、消息、通知、用户输入和停止请求绑定原始代次。未接纳的过期输入、旧内部工具 token、迟到结果、旧审批回复和旧 Abort 都不能进入或停止新运行。停止后新的明确人工发送读取最新代次并使用新 token，旧队列不会跟随重新激活。

请求 token 支持重试：配置操作及同一有效运行代次内的操作，相同 token 和内容返回已有结果，改变内容则冲突；内部消息的旧代次 token 不能用于新运行。主会话以磁盘上的 `accepted_input` 为输入接纳边界。已经接纳的主会话输入即使经历停止或重启，按原始身份和原始内容重试也只返回已有收据，不再次调用模型；未接纳的过期输入则拒绝。这保证接纳去重，不保证任意外部工具副作用恰好执行一次。

包含 Team 执行历史的会话暂不支持普通分叉、删除或改写最后一轮。自动工作区检查点、文件备份、回滚能力及整轮工作区锁已撤销；已有备份保留，独立 Git 和文件产物功能继续可用，详见[文件产物与 Git 管理](chat-checkpoints-git.zh.md)。项目删除会检查配置及运行快照的引用。聊天、重命名和继续提问保留。

## 存储和接口

- `${PILOT_HOME}/team-library/state.json`：角色和 Team 的当前配置、引用和配置操作收据；不保存角色或 Team 的历史修订。
- `${PILOT_HOME}/team-runtime/state.json`：运行段、冻结配置、历史任务、消息、轮次、实际请求发送记录、操作收据和 Team 人类交互记录。
- `${PILOT_HOME}/team-runtime/contexts/`：成员内部执行上下文和只读聊天 transcript 来源。
- 原项目聊天 transcript：用户和 Leader 的主会话，含持久化输入接纳元数据。

运行记录与配置库分别保存，使用校验和、原子替换和短期串行锁。配置库保存的是最新值；运行 activation 保存自己的成员快照。只要 Team 内仍有活跃 Agent Loop、排队工作、消息或通知，快照不会被配置编辑替换。成员工作和 Leader 回合都结束后，下一次空闲边界会重新读取最新 Team 配置。锁不覆盖模型或工具执行。

Gateway 的 `team_command` 保留配置管理操作，以及 `runtime_probe`、`runtime_select`、`runtime_get`、`runtime_stop`、`runtime_message_delete`。删除必须带会话、运行段、原消息代次、接收者和消息编号。人类交互和成员 transcript 另提供 `team_interaction_respond`、`team_participant_messages` 专用命令。Web `/api/team-library` 使用相同运行 action。普通 `submit_turn` 携带独立的 `teamSelection`，或者已绑定会话的 `teamActivationId` 与 `teamStopVersion`，不把 Team 伪装成模型名称。已绑定会话的 steer 和停止请求也需要原始运行代次；`runtime_stop` 使用 `activationId` 与 `stopVersion`。

运行日志升级为 v3，保留旧任务和 transcript，不恢复旧 pending。可从正式 transcript 证明的真实轮次恢复查询，旧 delivered 不追认为实际发送，标记为未知。损坏记录明确报错，不静默恢复运行。消息、轮次和交互列表可分页。`runtime_get` 返回持久化记录，`team_interaction_respond` 校验 Team/activation/participant/request owner 后定向返回原 Teammate，`team_participant_messages` 只读返回成员 transcript。

旧过渡版本的独立成员聊天不会恢复。旧配置库第一次修改前保留原始备份；旧启动收据和成员聊天绑定不参与当前运行。
